## 目的（なぜ）

COSMIC ID の計算ロジック(`src/calculations.js`)は純粋関数の集まりだが、ユニットテストが未整備。
このコードは「占い結果の正確さ」がユーザーの信頼に直結する土台であり、リグレッションを自動で検知できる状態にしたい。
あなたの成果物は、今後の改修で計算がズレたら即座に赤くなる安全網になる。

## 最初に読む（これがあなたの脳）

返答・着手の前に、以下を最後まで読むこと。ここが毎回変わらない土台になる。

- `AGENTS.md` — 規約・純粋関数の原則・**既知の検証値**・手動チェックリスト
- `README.md` — 19体系の一覧と各占術の入力
- `src/calculations.js` — テスト対象の実装本体

## 良い例（これ1個が指示10個に勝る）

AGENTS.md / README にある既知値をそのまま最初のテストケースにする：

- `1990-05-15` → ライフパス `3`、十二支 `午`
- `2024` 年 → 九星気学 `三碧木星`、十二支 `辰`
- `2000-01-01` → ライフパス `4`、九星は立春補正で `一白水星`（暦年のみなら九紫火星）
- `12/31` → 山羊座、`12/24` → 山羊座（冬至境界）
- 立春前(`2/1`)生まれの九星が前年扱いになること

## やること

1. `vitest` を devDependency に追加し、`package.json` に `"test": "vitest run"` を足す。
2. `src/__tests__/calculations.test.js` を作り、上の既知値を検証する。
3. `calculations.js` の **export されている純粋関数を網羅**する。境界値（立春・冬至・年またぎ）を優先。
4. 「今日」を入力に取る関数(`biorhythm`/`moonPhaseToday`/`dailyTarot`/`lifeStage`)は、**固定日付を引数で渡して**決定的にテストする。

## 制約

- **一番シンプルに通ることだけやる。** 抽象化・ヘルパー乱造・calculations.js 本体の作り直しは禁止。
- テストのために本体の入出力仕様を変えない。バグを見つけたら**直さずに報告**する（方針判断はこちらに委ねる）。
- 独立したテストファイル群は分身(サブエージェント)に分けて書かせてよい。最後は**まっさらな別の分身に、テストが実装の実挙動と一致しているか検証**させる。

## 止まる条件

止まってよいのは、既知の検証値どうしが矛盾している・仕様変更が必要・こちらにしか出せない判断が要るとき**だけ**。「あとでやります」を残してターンを終えない。

## 報告（結論から）

まず TLDR：`npm test` の**実際の実行結果**（pass/fail 件数）から書く。
- 全ての主張を実行結果と照合し、確認できていないものは「未確認」と明記。
- 失敗があればその出力をそのまま見せる。
- 気づいた学びは `docs/learnings/` に 1件1ファイルで記録（重複を作らず、誤りは消す）。
