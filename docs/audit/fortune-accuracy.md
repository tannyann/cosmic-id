## TLDR — ズレが大きい順

1. **マヤ暦 KIN: 起点が公式ドリームスペルと約131KINずれている疑い(最重大)**。公式では 2013-07-26 = KIN 164「銀河の黄色い種」とされるが、本実装は KIN 33 を起点にしている。事実なら**全ユーザーの KIN・紋章・音がすべて別物**になっている。さらに関連KIN(ガイド・オカルト)の式も公式ルールと異なる。→ 要Web照合(検証手順は§3)。
2. **動物占い: 60分類→12動物の縮約規則が公式対応表と不一致の可能性大**。公式の60分類は番号順に12動物が循環しない(動物ごとに番号が飛び飛び)。`(num-1) % 12` の単純剰余では別の動物が出る誕生日が多数あるはず。[未確認]
3. **九星気学: 本命星の式自体は標準どおり。ズレは「立春2/4固定」による年±0日〜1日の境界のみ**(影響は2/3〜2/5生まれの一部に限定)。一方、**月命星・日命星の簡易式は正式な求め方と別物**で、ほぼ全入力で乖離する。
4. **月星座: そもそも月星座を出しておらず「月相の傾向」を出している(別物)**。誤認リスクは表記次第。既に依存に入っている astronomy-engine で正式な月星座を計算可能。
5. タロット・バースカードの **22→`undefined` は流派差以前に実装バグ**(誕生日全体の約5%が該当)。詳細は parts/others.md §3 と `docs/learnings/`。

## 1. 九星気学(`kyuseiHonmei`, `kyuseiMonthStar`, `kyuseiDayStar`)

| 項目 | 内容 |
|---|---|
| 現状の式 | 本命星: 1月と「2月4日より前」を前年扱いにし、`11 −(西暦の数字和を1桁化)`(10→1, 0→9 補正)。月命星: `月+日` の数字還元。日命星: `日` の数字還元。 |
| 主要流派 | 本命星の式は気学の標準的な速算法と一致(園田真次郎系の九星気学で広く共有)。年の切替は**立春**が標準で、(a) 立春「日」で切替(多数派の実用)、(b) 立春の**時刻**(太陽黄経315°の瞬間)まで見る厳密派、がある。 |
| ズレる実例 | 立春は2/3〜2/5に変動する。**2021-02-03生まれ**: 実際の立春は2/3 → 正しくは2021年扱い(六白金星)だが、実装は前年2020年扱い(七赤金星)。**1984-02-04生まれ**: この年の立春は2/5 → 正しくは前年1983年扱いだが、実装は1984年扱い。[未確認: 各年の立春日は理科年表・国立天文台暦要項で要照合。2021年立春=2/3(124年ぶり)は報道多数で高確度] |
| 月命星の乖離 | 正式は「節入りで区切った生まれ月」×「本命星の三合グループ(一白・四緑・七赤/二黒・五黄・八白/三碧・六白・九紫)」による表引き。`月+日` の還元とは仕組みが違うため、**一致するのは偶然のみ**。例: 本命星一白・2月生まれの月命星は表では八白だが、実装は日付によって毎日変わる。[未確認: 表の具体値は気学書で要照合] |
| 日命星の乖離 | 正式は暦(万年暦)ベースで、冬至・夏至に最も近い甲子日を境に**陽遁(順回り)・陰遁(逆回り)**を切り替える。`日` の数字還元とは全く別物。 |
| 推奨対応(候補) | ① **立春日テーブル(1900〜2100)を持つ**: 数十行のデータで境界ズレが解消。おすすめ(コスト小・効果確実)。② 月命星を正式表引きに置換(表は小さい。中コスト)。③ 日命星は正式実装が重いので、「簡易式」であることを UI/README に明記して現状維持も選択肢。④ 時刻厳密派対応(出生時刻入力が必要)はプロダクト方針次第で見送り可。 |

## 2. 動物占い(`animalUranai`, `animalGroupIndex`)

| 項目 | 内容 |
|---|---|
| 現状の式 | 1925-04-23 起点の60日剰余で 1〜60 の番号 → `(num−1) % 12` で12動物 → `%3` で月・地・太陽グループ。 |
| 主要方式 | 個性心理學研究所(動物占い®の本家)の60分類は**四柱推命の日柱(六十干支の日)**をベースにしたものとされる。日の六十干支は連続60日サイクルなので、「起点日+60日剰余」という**枠組み自体は公式と同型**。合っているかは (a) 起点(位相)と (b) 60番号→動物の対応表、の2点で決まる。[未確認] |
| 疑義1: 起点 | 1925-04-23 が正しい位相か未確認。四柱推命の日柱と照合すれば機械的に検証できる(検証手順は§5)。 |
| 疑義2: 60→12の対応 | 公式の60分類表では、同じ動物が番号順に12個おきに現れる**のではなく**、動物ごとに番号が不規則に散っている(例: 狼は複数の離れた番号に割り当てられている)とされる。`(num−1)%12` の単純剰余は**ANIMAL_NAMES の並び順に依存した独自マッピング**であり、公式表と一致しない誕生日が相当数あるはず。[未確認: 公式換算表との突合が必要] |
| 疑義3: グループ | 公式の MOON/EARTH/SUN は**動物単位で固定**(例: こじか・黒ひょう・ひつじ・狼系…)。`idx % 3` は配列順序依存で、公式のグループ分けと一致する保証がない。[未確認] |
| 法務注意 | 「動物占い」は登録商標。公式の60キャラ名・解釈文の転載は不可。**計算方式の互換**と**表記(「12動物タイプ(独自)」等)**は分けて判断すること。 |
| 推奨対応(候補) | ① 四柱推命の日柱計算(万年暦アルゴリズム)で位相を検証し、ズレていれば起点だけ修正(おすすめ・第一歩)。② 60→12対応表を公式互換のデータテーブルに置換(要調査+法務確認)。③ 「独自の簡易12分類」と明記して現状維持(最速・誠実)。 |

## 3. マヤ暦 KIN(`mayaKin`, `mayaRelatedKin`)

| 項目 | 内容 |
|---|---|
| 現状の式 | 2013-07-26 = KIN 33 を起点に、実日数(うるう日含む)の260剰余。関連KIN: ガイド=+19、アンチポッド=+130、オカルト=+65。 |
| 主要方式 | 日本の「マヤ暦鑑定」系はほぼ**ドリームスペル(ホセ・アグエイアス、13の月の暦)**準拠。学術的な**伝統ツォルキン(GMT相関、JDN 584283)**とは別系統で、両者のKINは一致しない。 |
| **疑義1: 起点が誤りの可能性(最重大)** | ドリームスペルの年は7/26開始で、**2013-07-26 は KIN 164「銀河の黄色い種」**(銀河の同期として著名な日)とされる。独立の照合: 2019-07-26 = KIN 14「磁気の白い魔法使い」とすると、ドリームスペル年は365日=+105KIN/年なので 14 − 6×105 ≡ 164 (mod 260) → 整合。**本実装の KIN 33 とは 131 KIN の恒常ズレ**になる。[未確認: 13moon.com 等の公式計算機で要照合。ただし内的整合性チェックは通っており高確度] |
| 疑義2: うるう日 | ドリームスペルは **2/29 を「KIN を持たない日(0.0 Hunab Ku)」としてスキップ**する。実日数カウントの本実装は、うるう日を跨ぐごとに公式から1ずつ位相がずれる(起点ズレに加えて累積ズレ)。例: 起点が正しくても 2/29 を n 回跨いだ過去日付は n だけずれる。[未確認だがドリームスペルの著名ルール] |
| 疑義3: 関連KIN | アンチポッド(反対)= +130 は**正しい**。オカルト(神秘)は「2つのKINの合計が261になる相手」= `261 − kin` が公式で、+65 は誤り。ガイドは固定オフセットではなく**音(トーン)によって決まる**: 音1・6・11=自分と同紋章、音2・7・12=紋章+12、音3・8・13=紋章−4、音4・9=紋章+4、音5・10=紋章+8(トーンは自分と同じ)。[未確認: オフセット値の細部は要照合。「固定+19は公式ルールではない」ことは高確度] |
| ズレる実例(検証用) | 2013-07-26(KIN 164 のはず→実装33)/ 1997-07-26(KIN 22「太陽の白い風」とされる年初日 [未確認])/ 2/29 を挟む連続日: 2020-02-28・2020-03-01 で公式は連続KIN、実装は+2。 |
| 推奨対応(候補) | ① 公式計算機と3〜5日付を突合して起点を確定 → **起点定数の修正+うるう日スキップの実装**(おすすめ: 既存構造のまま直せる)。② 関連KINを公式ルール(オカルト=261−kin、ガイド=音依存表)に修正。③ あえて独自方式を維持するなら「簡易KIN(独自)」と明記(既存ユーザーの結果が変わらない利点はある)。**修正すると全ユーザーの結果が変わるため、告知方針とセットで判断すること。** |

## 4. 月星座(`moonTrait`, `birthMoonPhaseIndex`)

| 項目 | 内容 |
|---|---|
| 現状 | 月星座は算出せず、平均朔望月(29.530588日)による**月相4分類**(新月期/上弦期/満月期/下弦期)を「月の傾向」として表示。 |
| 妥当性 | 月相占星術(moon phase astrology)は実在する体系であり、「月相の傾向」という表記なら虚偽ではない。ただしユーザーが期待する「月星座(蟹座の月、など)」とは**別物**なので、カード文言で混同させないことが重要。 |
| 平均朔望月近似の誤差 | 実際の朔望は ±数時間〜半日以上ずれる(月の軌道離心率による)。4分類の境界日付近では**分類が1つ隣にずれる日が出る**。[未確認: 具体的な境界実例は天文暦で要照合] |
| 正式な月星座の実現手段 | **astronomy-engine は既に package.json の dependencies に入っている**(スターマップ/今夜の空機能で使用中と推測)。`GeoMoon`/`EclipticGeoMoon` 系 API で月の地心黄経を出し、30°ごとに区切れば月星座になる(精度は用途に対し十分)。追加コスト小。 |
| 出生時刻問題 | 月は約2.2〜2.5日で星座を移動する。出生時刻不明の場合は**正午で計算し、その日の内に星座が変わる境界日だけ「◯◯座または△△座」と両方示す**のが誠実(境界日は全体の約2〜3割)。[未確認: 業界慣行としての普及度] |
| 推奨対応(候補) | ① astronomy-engine で正午基準の月星座を新カードとして追加し、境界日は両候補表示(おすすめ: 依存追加ゼロで「19体系」が1つ本格化)。② 現状維持なら「これは月星座ではなく月相の傾向」であることをカード内で明示。③ 出生時刻の任意入力欄を足して確定計算(UX判断)。 |

2. **動物占い**: 公式系の無料判定(doubutsu-uranai.com 等)で誕生日5件を照合 → 起点と60→12対応の正否が確定。
