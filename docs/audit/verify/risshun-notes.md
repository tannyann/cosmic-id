# 立春日テーブル(1900–2100)検証ノート — I-3

作成: 2026-07-14(GitHub Issue #3)

## TLDR

- `src/data/risshun.js` に 1900–2100 の立春日(JST)を機械生成。201年分、欠けなし。
- 既知値照合は **3/3 一致**(2021=2/3、1984=2/5、2000=2/4)。
- 2/4 以外の年は **72件**(2/5 が 38件・すべて1984年以前、2/3 が 34件・すべて2021年以降)。
- `npm test` 全pass(77 tests / 2 files)。calculations.js は未変更(組み込みは I-8)。

## 生成方法

- **定義**: 立春 = 太陽の視黄経が 315° になる瞬間。
- **計算**: `astronomy-engine`(package.json 既存依存)の `SearchSunLongitude(315, start, 25)` で
  各年1月20日(UTC)起点・25日窓で探索。ΔT(地球自転の遅れ)はライブラリが内部補正。
- **JST換算**: 得られたUTC時刻に +9時間して日本時間の「日」を取る。
- **再生成**: `node src/data/risshun.gen.mjs`(生成前に既知値照合を自走し、失敗したら生成を中止する)。
- 特定の暦注(◯◯流の暦)ではなく、**天文計算(太陽黄経315°のJST日付)を採用**。
  国立天文台の暦要項も同じ定義(太陽黄経315°・中央標準時)で二十四節気を定めているため、
  原理的に一致する想定。

### 外部照合の状況

国立天文台 暦要項での1〜2年分の裏取りは、WebSearch がセッション上限に達したため**未実施(未確認)**。
上記3年の既知値照合のみ完了。**3年以外の年は astronomy-engine の天文計算による値であり、
暦要項との突合は未確認**。ただし 2021 の「JST 23:59」のような際どい境界も正しく 2/3 側に
落ちていることから、定義(黄経315°・JST)レベルの実装ミスはないと判断している。
後続で暦要項(https://eco.mtk.nao.ac.jp/koyomi/yoko/)と数年分突合することを推奨。

### パターンの妥当性

- 1985〜2020 は全年 2/4。「2/4固定」近似が有効だったのはこの期間だけで、
  1984以前生まれ・2021以降の年運計算では最大1日ズレる — Issue #3 の問題意識と整合。
- 2/5 は 4年周期(閏年前後)で古い年に、2/3 は 2021 以降に増えていく。
  1太陽年 ≒ 365.2422日と閏年のずれの蓄積として知られる挙動と一致する。
- 2/2 は 1900–2100 に存在しない(テストで範囲 2/2–2/5 を許容しているが実データは 3〜5日のみ)。

## I-8 への引き継ぎ

- `import { RISSHUN, risshunDay } from './data/risshun.js'` で参照できる。形は `{ 年: [月, 日] }`。
- `kyuseiHonmei` 等の年切替を「2/4固定」からこのテーブル参照に置き換えるのが I-8 の仕事。
- 範囲外(1899以前・2101以降)は `undefined` が返るため、フォールバック(2/4扱い等)の方針を I-8 で決めること。
